# Persistent JSON maps and key capabilities

This checkpoint adds complete typed map storage and conversion to the existing value/codec layers. `JsonKey` supplies the application label, total comparator and independent name encode/member decode callbacks. `JsonMap` uses persistent balanced storage, preserves null separately from an allocated empty map and retains unrelated prior members during updates. Its constructor, insertion, lookup, size and ordered entry APIs are concrete implementations. It does not use runtime reflection.

`json-string-key`, `json-int64-key` and `json-uint64-key` provide primitive key rules. `json-key` adapts scalar text methods, `json-byte-key` adapts arbitrary byte-name methods, and `json-json-key` composes an existing typed JSON capability with numeric stringification and explicit refusal of nonstring name tokens. An explicitly unsupported key capability remains distinguishable from a valid JSON capability that produces an invalid member-name token. `JsonInvalidValueError` represents the latter without inventing a type or value object.

All converted names are normalized and privately snapshotted before any value-encoding callback runs. The inspected emitted ASCII traversal contains a machine-counter backedge and a final tail call, with ownership retained outside the scan; it does not allocate or refine a natural index per sixteen-byte block. Complete ASCII intervals use the production load-only sixteen-byte LLVM classifier; fringes use checked intervals and a one-byte load. Non-ASCII scalar validation is explicit. Invalid UTF-8 is repaired before both sorting and quoting. Sorted output uses encoded UTF-8 name order; equal encoded names retain application-comparator order. The reference implementation does not specify a deterministic order for distinct keys with equal repaired names, so the independent byte-exact fixtures avoid that unspecified tie. Keys must retain stable total ordering while stored; owned immutable map updates do not grant permission to mutate an ordering-sensitive application key.

`json-member-key` retains the original quoted name token through its source document. It provides exact escaped spelling and byte positions in constant time, and supports ordinary string views. Raw source exports remain copies. Typed key failures retain the original member-token end and path; custom callback failures preserve their cause. Decoding retains the first error and partial map according to the configured continuation policy. New map elements use fresh defaults under the default policy.

The independent corpus has 61 typed update/encoding observations and nine raw-name encoding observations. Nine additional control groups cover source/export aliasing, persistent prior values, null/empty distinction, error continuation, all-name-before-value callback ordering, mutable callback buffers and complete encode/decode/lookups of 5,000 entries. Ordinary runs retain 32 MiB heap and 8 MiB stack; separate poisoned-free runs use 256 MiB heap and the same stack. The compiler host main stack is explicitly 64 MiB, independently of consumer limits.

A Native lowering refusal was found in a fixture's generalized computed empty-map binding. The exact failing source and emitted diagnostics remain under `build/json-codec-map-native-v1/map-control`; a deterministic compressed copy plus source/runtime receipt is published under `compiler/repros/json-map-native-polylet-original`, and the standalone diagnostic sources are checked in as `json-map-polymorphic-let.cinch` and `json-map-polymorphic-let-annotated.cinch`. The portable control gives that binding its intended `JsonMap String I64` type. This fixture annotation changes neither library contracts nor checker rules. Fresh compiler comparisons are recorded as separate epochs. Both smaller standalone candidates emit successfully under the final 2f077 compiler: neither is a confirmed reproduction, and the exact original full bundle has not been tested with that compiler.

`../evidence/stdlib/stdlib-json-map-evidence.json` identifies the exact selected sources, consumers, seed/provider/runtime epochs and receipts. Historical pre-normalization receipts remain labeled separately. Foreign object checks exercise the actual production classifiers, without claiming foreign execution. No public JSON performance improvement is claimed: paired public-pipeline benchmarks and lowering review remain open.

The package remains partial across the full 92 audited declaration records. Binary32, dynamic values, general raw numeric string conversions, complete method/record-error adapters, legacy bridges, bounded incremental decoding/encoding and their public pipeline comparisons remain work for subsequent checkpoints.
