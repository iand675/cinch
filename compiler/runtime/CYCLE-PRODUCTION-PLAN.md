# Ownership-cycle production review plan

Status: static proposal, **no implementation selected or production hook enabled**. The nine-unit test-only prototype is commit `5a0586eaf2a130214cb904b1c91f4d84092dee29`, based on source `9bc5237aede73322b100b5ac2d58c4f4d1a90f20`. Its local registry is not a production lifetime authority.

The current observed library case is separately qualified at source `75b4bab70d18ed3dd66bf6b8c5153943764dabf3`, compiler `330adb4d77f8bcbfc26f246269280f391c3a10b6d3a40771b5f6243f6a8969b2`, runtime `d91ce012395a99e1148232d20ec316979cd7d0cb13647a3283ba4820192c0abf`. Buffered checkpoint `bbbea08e34f530cc47c1ec50b3ea72141e27a3ac` observes an actual 22-block leak in both fixed profiles **after** exact two-byte transfer, positive-read EOF, zero-byte transfer and completion-marker assertions. It also retains the independent passing four-group transfer controls and the original historical failures. The count is evidence for this case, not an algorithmic constant.

## Recommendation and selection gates

The smallest candidate worth implementing next is a context-independent, non-owning candidate registry plus an explicit quiescence protocol around the existing bounded trial-deletion algorithm. That is a proposal for a positive-graph collector, not a claim that all legal cycles are covered. Removing `cfg(test)` from the thread-local prototype, collecting during allocation, or making leak-check activation trigger collection is unsound or changes the diagnostic's meaning.

Two issues block selecting a complete production solution:

1. A full mutator/foreign-entry quiescence protocol and owned-backing proof must be demonstrated, including suspended fibers and parallel output initialization.
2. Negative-count/shared cycles remain excluded. No atomic mutable payload tracing or demotion is authorized here. The language permits task bodies with an open effect row and one-shot ownership transfer, so Region annotation alone is not evidence that a buffered graph can never become atomic. Actual source tests must establish which buffered transfers are accepted. If a legal transferred/shared callback graph becomes atomic, positive-only reclamation is an incomplete fix. Supporting that case would require a separately reviewed synchronized shared-graph collector or another proven ownership solution; it cannot be claimed covered by an opaque boundary.

The existing capture checker rejects exclusive `Mut` borrows and requires shareability or single transfer, but an IO+Mut effect row is not itself an exclusive-borrow type. Its rules must be used as written, rather than treating every region-indexed value as thread confined.

## Candidate safety invariants

1. **Lifetime without ownership inflation.** A process/context-independent registry stores non-owning allocation identities. Retirement happens before free, poisoning, atomic publication and reuse. A collector snapshots identities only under an exclusive world epoch. Persistent metadata must validate allocation generation; no pointer from an earlier resumed epoch is dereferenced merely because an address matches. Registry allocation failure cannot leave an apparently complete but incomplete census.
2. **No overlapping mutation.** All managed execution, parallel initialization, RC reversal, foreign entry and result publication must participate in the world protocol. A request is deferred when any participant is foreign-active or cannot park safely. It must not wait while holding a runtime resource mutex needed by that participant. No user callback, foreign code or scheduler yield runs in the graph detach phase.
3. **Root authority.** Every live borrowed reference at an admitted safepoint has an independently owned counted backing root or an explicitly registered foreign owner. Suspended contexts and Rust-owned task-result slots retain their existing owners. Nominal Region proves scope relationships, not a thread ID, a root enumeration, or a permission to drop its values.
4. **Precise supported graphs.** Only fully initialized, stable positive heap nodes with reviewed precise `Scan` rules participate. Frame markers, negative counts, active memo/knot initialization, MVar/TVar and unreviewed resource state abort or remain opaque by an explicitly conservative rule. Opaque boundaries are never scanned. A new runtime kind cannot silently enter the eligible set through a numeric range check.
5. **Shadow classification.** Actual headers/counts are unchanged during discovery. Every counted internal slot contributes one incoming edge, including duplicates. `rc - internal incoming > 0` seeds liveness and its full forward closure. Inconsistent counts, changed header/slot, unsupported nodes or incomplete budget cause no graph mutation.
6. **Atomic detach and disposal.** Detach all counted edges of a fully proved dead component before disposing any member. Release external edges exactly once through ordinary ARC; dispose blocks through the existing destructor/free path. Retirement is nonreentrant with registry/world locks, and any destructor that may enter managed code must be excluded until a separate protocol exists.
7. **Budget honesty.** Bound attempted roots, nodes, edges, scanned words, metadata bytes and collection work. An aborted component remains exactly intact. A cursor prevents a large/live component starving unrelated candidates. Increasing a future budget requires a new stable snapshot; cached raw graph edges cannot survive resumed mutators without a write-barrier/version scheme. A hard budget is not evidence of eventual collection of a larger cycle. Resource exhaustion and residual leak diagnostics stay truthful.
8. **Independent diagnostics.** Collection is never conditional on `CINCH_LEAK_CHECK`. With and without that flag, any admitted collector event has identical ownership behavior; the flag changes reporting only. Unregistered/unsupported genuine leaks must still produce the actual nonzero report and failure. Neither the observed 22 nor any other leaked count is subtracted from statistics.

## Quiescence stages proposed for review

The first production-oriented experiment should remain a distinct runtime epoch with no general allocation-time collection. A global side registry removes the known OS-thread-local lifetime error. A test-invoked world barrier should then prove that it can stop all registered managed contexts, wait out active parallel initializers and exclude native/FFI activity. This is stronger than the prototype caller's unsafe local assertion and can be tested before any automatic trigger is enabled.

The proposed barrier has explicit epoch states, rather than deriving readiness from reference-count signs:

1. A logical managed context owns an admission lease while running. Its identity follows fiber migration. Native managed exports and externally called ownership operations need an admission protocol too; merely wrapping `Blocking` imports misses these entries.
2. Requesting epoch `E` prevents a newly admitted mutator from starting without joining that epoch. A context acknowledges only at a reviewed fully initialized, owned-backed boundary and stays parked until `E` completes or is canceled. Already parked contexts retain their counted owners and may not resume through a wakeup while the barrier owns the world.
3. Every active parallel initializer and pointer-reversal RC/mark walk holds a nonquiescent lease. Foreign activity holds a separate active lease, including nonblocking imports, retained native work and nested callbacks. An outer foreign lease must not wait for a nested callback to park: if foreign activity prevents the barrier, defer/cancel the request before taking graph authority. Never hold a resource or registry lock while waiting for participants.
4. Only all acknowledged contexts, zero active initializers/RC walks, and zero unresolved foreign entries permit a stable registry snapshot. A bounded handshake that cannot reach this state returns **deferred**, releases parked participants and reads no candidate payload. It does not forcibly suspend an uncooperative native thread or label a partially stopped world quiescent.
5. Collection is nonreentrant. Its host metadata allocation cannot recursively trigger managed collection. Before the first detach, reserve/charge the bounded metadata and validate every chosen complete component. Disposal must be proved not to call user/foreign code or release an excluded state whose destructor reenters the managed world; otherwise defer that component. After ordinary disposal and registry retirement, advance the epoch and release participants.

This state machine still needs implementation-level race tests and root proofs. In particular, an existing foreign ownership operation called by an unregistered C thread cannot be made invisible merely because its ABI currently has no collector token. An equivalent admission mechanism inside existing entry points may preserve their signatures, but it must be demonstrated before using the no-ABI-change claim.

An entry-epilogue phase is a possible first automatic trigger, **not approved integration**: after the entry returns, all structured cleanup, worker joins and external active entries must be proved settled before collecting independently of leak checking. Persistent native worker threads and dormant fibers still need explicit participant states. This would address shutdown reclamation only. It is not a bounded-memory solution for long-running programs.

Long-running reclamation would additionally need compiler-admitted safe boundaries, such as a poll after fully initialized construction at a loop/backedge or an already valid runtime boundary. A compiler-visible new entry is not covered by the current no-ABI-change constraint and requires separate review; it is not selected here. The runtime-only first experiment must keep the existing exported ABI, header encoding, pointer maps and actual counts unchanged. Allocation pressure may request a future pass, but allocation itself must not collect half-built objects. All live owners/borrows must remain visible in ordinary counts, and LLVM must not move initialization/releases across the boundary. Where foreign activity blocks a safe pass, defer rather than asserting quiescence or stopping an uncooperative native thread. Latency/progress and heap/metadata exhaustion behavior require an explicit contract before selecting this phase.

## Weak-reference/control-block comparison

A plain weak back-edge is smaller but violates the required API. A retained transfer callback must still work after the separately returned opposite handle is dropped. Making that callback weak can expire a live operation; keeping it strong recreates the observed cycle.

A shared bridge control block does not automatically solve this. If callbacks own the bridge strongly, and the bridge owns the advanced source/sink whose user closure retains those callbacks, the bridge points back to itself. If callbacks are weak, a callback retained by arbitrary user storage can outlive both visible handles and lose its state. Distinguishing internal captures from external copies would require new compiler/store/FFI escape accounting or generic external-root tracing. Returned source/sink closures are opaque to Core, so it cannot safely rewrite their captured references. Requiring callbacks to expire, forbidding retention, or adding disposal would narrow the contract and is rejected.

A weak/control-block proposal is selectable only if it proves all retained-callback/advanced-alias cases without expiry or mandatory disposal and accounts for arbitrary heap/FFI storage. No such smaller general proof is currently available. The existing precise-graph approach is the stronger basis for investigation, with the stated shared-graph gap still open.

## Required concrete gates before implementation selection

Only the original nine local prototype units have run. Every item below is a proposed new gate, not a passed result.

| Gate | Required observation |
| --- | --- |
| Current real callback graph | Relink the unchanged `bbbea08e` source against a separately identified candidate runtime. Completion marker and exact transfer/EOF checks remain; eventual zero live/leaks must be actual, in normal32M/poison256M/8M. Existing d91 failure stays plain. |
| Retained external owners | Keep either advanced handle, either transfer callback, a copied callback inside another closure/array, and a foreign owned handle across passes. Invoke them afterward; state/progress/capability changes remain authoritative. Release only the final external owner before expecting reclamation. |
| Concurrency legality | Actual source checks for moving a buffered graph through a one-shot task, returning a newly created graph, and any shared capture. Record accepted cases and exact genuine refusals. Do not infer physical confinement from Region syntax. |
| Result transfer/migration | Repeated positive result handoff, failed/canceled/unjoined results, producer-thread teardown, and parked-fiber resumption on another worker; no stale entries, double free, premature release or forgotten dead graph. |
| Positive parallel initialization | Hold writers at deterministic barriers while a collection is requested; no payload inspection before every initializer joins. Empty queues with a running job must not authorize a pass. |
| Shared boundary | Concurrently change an excluded atomic child's payload and MVar/TVar queues; count actual scan reads and require zero payload reads. A legal atomic buffered cycle must be explicitly reported as uncovered until an approved shared algorithm exists. |
| FFI/reentry | A blocked foreign call, retained owned callback, native-thread managed export, nested callback and FFI-held owner survive. A pending collector must defer without deadlocking a resource lock or treating native execution as parked. |
| Allocation and free races | Free/reuse candidate addresses on another worker, mark during publication, debug poisoning, system fallback allocation and parked allocator remote-free queues. No registry lookup may dereference an old generation. |
| Budgets and unchanged state | Node/edge/word/root/metadata caps at exact boundaries; incomplete pass preserves every header and slot, count1 remains1, a later sufficient fresh pass reclaims. Large iterative rings and live shared tails must fit the fixed native stack. |
| Normal semantics and diagnostics | Four transfer groups plus complete noncycle buffered corpora remain zero-leak. Collection behavior is equal with leak checking off/on; intentional unrelated leaks still report and fail. Collector-disabled frozen runtime still reproduces its known failure. |
| Portability and overhead | Both compiler pipelines, ownership/frame/tail/FFI gates, single-thread cooperative backend and supported object targets; no foreign execution claim from compilation alone. No callback narrowing, count inflation, ABI/header-layout change, atomic-payload tracing, leak-check exemption or production safepoint is selected by this document.
