# Opt-in retained parent qualification

This is a static proposal. Rustfmt parsed the Rust changes, Python AST checks passed and every Python helper/class/method has a docstring. No child Cargo build, test, archive or deduplication was executed. Root is separately qualifying the actual parent producer.

The exact patch applies to `compiler/tests/lib_json_codec.rs` with base SHA `730b8e34ad2909312f44850de07940b6a5362bb2265dfa96da5dac4343467987`. Its patched SHA is `8d7c84d55093dc228d8e59aa72c0ae0354ff1e056233533485273a15fecdd610`. It preserves all 42 test names and the existing source closure, runtime assertions and panic-retention behavior. Both own-lane and imported Root files were byte-identical before the patch; their patched bytes were also checked equal. Root has already applied this patch; do not apply it a second time.

`CINCH_KEEP_QUALIFICATION_PROJECTS=1` keeps named projects in the caller's `TMPDIR`. Failed projects always remain. A runtime `qualified.json` is atomically published only after the existing normal and poison assertions both pass. It records all source/CIF/artifact hashes and sizes, mode/uid/gid/nanosecond mtime, the current compiled test producer hash, warm linked runtime identity before/after, and exact run stdout/stderr bytes, statuses, heap/stack/poison/leak settings. Portable objects have a distinct `portable-qualified.json` only after all three target compilations; documentation-only checks legitimately create no project. Portable objects are never represented as executed runtime profiles.

The actual static inventory is **31 existing + 11 added = 42 tests in both lanes**. Earlier 34/45 metadata was a counting assumption, not an executed target count. The external driver discovers the actual compiled target's names, checks its explicitly supplied count and the eleven new names, and records them. It never copies extra tests from another lane.

Root launches the driver only after review, using its actual current producer/runtime/BDF context JSON and existing warm cache. Source the normal tool environment before starting: the Cargo wrapper sources it only inside its own child and cannot update the supervisor's environment.

```bash
source /workspace/.tools/cinch-env.sh
python3 -B /workspace/dasl-stdlib-json/bootstrap/repros/json-parent-retention-next/run_json_parent_gate.py \
  --compiler-root /workspace/dasl-stdlib-io/compiler \
  --work-dir /workspace/dasl-stdlib-io/build/json-syntax-parent-retained-v1 \
  --expected-tests 42 --baseline-tests 31 --added-tests 11 \
  --release --context /ABSOLUTE/PATH/TO/ROOT-ACTUAL-PROVENANCE.json \
  --apply-passed-input-dedup
```

The provenance path above is deliberately a placeholder for Root's actual context; no child 855/c4 identity is substituted. The work directory must be new. Root's separate release no-run build can finish first; the driver's identical Cargo no-run invocation should then be a warm no-op. Its separately reviewed build cap defaults to 160 MiB and needs at least cap + 250 MiB free before start. The driver does not restore old test executables or libraries.

Each discovered test runs in a separate process with `--exact`, on CPU3. Every phase needs 350 MiB initial free; the supervisor soft-pauses the entire process group below **270 MiB**, before the 250 MiB reserve. Each complete test has a 30 MiB fresh output cap. Two pre-existing tests create two projects; BOTH count toward that test's cap, and no first-project artifact is archived before the WHOLE test succeeds. Historical Dynamic basic/edge functional ELF+IR already totals roughly 40 MiB before source/CIF, so that test may require a separately reviewed scoped resource decision. No cap is silently widened and no test is split or dropped.

After a successful test process, the driver verifies every expected project marker and file. Only then does it archive `consumer` and `consumer.ll`; all sources, CIF, object-only evidence, diagnostics and failure artifacts stay plain. Archive creation is limited to 10 MiB scratch, and compressed/decompressed hashes plus member SHA/size/mode/uid/gid/exact nsmtime are verified. The archive and immutable recovery index are fsynced with their parent directories BEFORE unlink; original identities are rechecked, then the project parent is fsynced after unlink. Any failed marker or process prevents all archival for that test.

On a soft resource/deadline pause the supervisor remains alive and the process group stays stopped. The numbered `pause-NNN.json` names a matching `RESUME-NNN.json`. Root must explicitly create that request with `action: "resume-existing-process"` and a nonempty `approval` string; fresh 350 MiB is still required. A deadline needs an explicit positive `additional_active_seconds`; a cap change requires an explicitly reviewed `cap_bytes`. Those are scoped operator decisions, not automatic approval. Requests and applied decisions remain in the evidence directory; elapsed time alone never resumes a process or enlarges a budget. Root should not independently SIGCONT the child while the supervisor is alive. If the supervisor itself is lost, the pause record retains the group ID and exact command; inspect and explicitly recover the existing group rather than relaunch into retained projects. Default build/test caps remain 160/30 MiB until such a separately approved scoped decision.

Passed-input deduplication is **dry-plan-only by default**. Root's explicit `--apply-passed-input-dedup` enables the reviewed sealed-success policy after each successful test and archive. Only project-owned `.cinch` and generated `.cinchif`/`.cif` files for those same on-disk module names qualify; embedded-only provider interfaces and ABI/runtime/compiler/frozen/benchmark inputs are excluded. No new writable project is prelinked. Independent full hashes, full byte comparison, size, mode and actual uid/gid must match an already successful canonical project. The original per-path metadata, including nsmtime, and canonical visible timestamp are durably indexed BEFORE replacement. All paths remain plain and those projects must never be compiled again. Shared mtime consolidation is explicit; recovery copies canonical bytes into a separate inode and restores the recorded original mode/uid/gid/nsmtime. Ledger output is capped at 5 MiB. The exact per-project plans and applied indices remain available for inspection.

No runtime/source validation is claimed for this proposal. Fresh actual Root test execution remains authoritative. Full JSON streaming/Effect.Json, Native, public pipelines and final package reconciliation remain open.
