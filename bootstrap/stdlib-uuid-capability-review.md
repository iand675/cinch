# UUID capability review

The pinned SDK exposes exactly13 declarations. `stdlib-uuid-reference-surface.json` records their exact text, SDK executable identity, source/test hashes and the `audit_stdlib_surface.py --package uuid` command. That command inspected the actual SDK API files and ran no reference build. No UUID implementation or representation is selected, no shared inventory status changes, and no package completion is claimed.

| Actual declaration | Required behavior | Proposed idiomatic capability |
| --- | --- | --- |
| `type UUID [16]uint8` | All128 bits are values, with value equality and direct16-byte construction/access; nil/max and unknown versions remain valid values. | Opaque `Uuid` plus checked exactly16-byte conversion and lossless byte output, `Eq`/`Ord`/hash over complete bits. Representation stays open. |
| `func Nil() UUID` | All16 bytes zero. | Pure `uuid-nil :: Uuid`. No absent/null handle is introduced. |
| `func Max() UUID` | All16 bytes255. | Pure `uuid-max :: Uuid`. No ordinary version/variant validation rejects it. |
| `func Parse(string) (UUID, error)` | Accept canonical36-character hex with fixed dashes, brace-wrapped38, exact lowercase `urn:uuid:` prefix plus canonical36, or undashed32. Hex letters may use either case. Other lengths/punctuation fail. No trimming, nested form combination or version-bit validation. | Pure `uuid-parse :: String -> Result UuidError Uuid` and a byte parser for text adapters, with exact acceptance and named errors. |
| `func MustParse(string) UUID` | Same success value as Parse; invalid input panics. | Untrusted runtime input uses the total parser. A separately checked definition-time literal can cover trusted literal convenience if an existing staging facility supports it. A public runtime panic wrapper is an explicit unresolved adaptation; it is not silently counted as implemented. |
| `method (*UUID) UnmarshalText([]uint8) error` | Identical accepted forms; invalid input leaves every receiver bit unchanged. Success replaces all16 bytes. | Pure byte parser plus an optional `Var r Uuid` adapter with `{Mut r}` that commits only after success. Retained receiver aliases must see one complete successful replacement and no mutation on refusal. No new mutable UUID object hierarchy is needed. |
| `method (UUID) String() string` | Always36 lowercase ASCII characters with dashes at8/13/18/23. | Pure `uuid-format :: Uuid -> String`. |
| `method (UUID) MarshalText() ([]uint8, error)` | Same36 bytes; current encoder has no value-dependent error. Returned bytes may be independently mutated. | Pure `uuid-text :: Uuid -> Bytes`, with clear immutable byte ownership/alias guarantees. |
| `method (UUID) AppendText([]uint8) ([]uint8, error)` | Preserve an arbitrary existing prefix exactly and append canonical36 bytes; errors are always nil in the inspected source. | Pure append returning fresh immutable bytes (or an explicitly scoped destination adapter). | `method (UUID) Compare(UUID) int` | Lexicographic unsigned big-endian byte order, returning negative/zero/positive according to all128 bits. | Pure `uuid-compare :: Uuid -> Uuid -> Ordering`, consistent `Ord`, with a numeric ordering adapter only where needed. No signed-word or host-endian ordering. |
| `func New() UUID` | Current source chooses V4; algorithm choice is the default policy. | Explicit IO operation selecting the documented default; no nondeterministic pure constant. Keep the policy distinct from the named version constructors. |
| `func NewV4() UUID` | Draw16 cryptographically secure random bytes, preserve122 random bits, overwrite version nibble4 and RFC variant bits10. | Pure constructor from exactly16 supplied entropy bytes plus an IO adapter that obtains secure randomness. Never use a fast noncryptographic PRNG as the default. |
| `func NewV7() UUID` | Timestamp/random construction and serialized state, with ordering and rollback details below. | Pure transition over explicit `UuidV7State` and supplied time/entropy, plus a separately owned, serialized IO generator. No implicit process-global mutable cell in a pure module. |

Pure operations belong at a proposed `Data.Uuid` home; scoped receiver adaptation can be separate; entropy/clock acquisition and synchronized generator ownership belong at `Effect.Uuid`. Suggested pure seams are `uuid-from-bytes :: Bytes -> Result UuidError Uuid`, `uuid-to-bytes :: Uuid -> Bytes`, `uuid-parse-bytes :: Bytes -> Result UuidError Uuid`, and `uuid-v4-from-random :: Bytes -> Result UuidError Uuid`. `UuidError` must distinguish text/length refusal, target append-capacity refusal and explicit time/state range refusals where applicable. A generator callback that offers recoverable entropy errors may retain them, but current `Effect.Random.random-bytes` has no recoverable error result; this review does not invent one for that existing provider.

The inspected V7 source stores a60-bit logical timestamp:48 millisecond bits followed by12 bits computed as `floor(submillisecond_nanoseconds *4096/1_000_000)`. It remembers both whole Unix seconds and the last logical timestamp. If the current whole seconds value moves backward, it discards the previous ordering constraint; otherwise a timestamp no greater than the previous one is incremented. Consequently a subsecond rollback within the same whole second still advances the logical timestamp. Repeated-time increments can carry into the next millisecond. Version7 is inserted into the timestamp word, and the final8 random bytes are drawn before masking the variant to10, leaving at least62 random bits. The mutex serializes the timestamp state transition; random acquisition occurs after that lock is released. Concurrent completion order must not be mistaken for a total order over overlapping calls.

A proposed pure seam is `uuid-v7-step :: UuidV7State -> Nat -> Bytes -> Result UuidError (UuidV7State, Uuid)`, with input time defined explicitly as Unix nanoseconds and exactly8 entropy bytes. Its state must retain whole seconds and the full logical timestamp to reproduce rollback behavior. New state is returned only on a checked successful transition; malformed entropy, out-of-range time or exhaustion must not silently wrap into another era. The timestamp field has a48-bit millisecond range; current `Effect.Clock.clock-wall-ns` is more narrowly bounded by its provider's signed64-bit nanosecond range, so pure construction and existing IO-provider coverage must be recorded separately. Behavior for pre-epoch or otherwise unrepresentable times requires a named policy rather than an unchecked integer cast.

Each explicit generator defines one ordering sequence. Independent generators do not establish a process-wide total order. Sharing one handle across callers needs a genuinely serialized state capability; ordinary `Var` mutation alone is insufficient under concurrency. The lock/state provider and its complete effect row must be qualified before choosing an IO generator API. Native MVar source/backend work is still a separate lane, so this review selects neither that dependency nor a public effect signature prematurely.

The parsing/formatting hot paths merit SIMD/SWAR through checked inline LLVM/ASM or existing qualified Hex workers: classify32 hexadecimal lanes in bounded chunks, reject non-ASCII and invalid punctuation exactly, decode nibble pairs, and encode16 bytes to lowercase hex before fixed dash placement. Keep scalar length/wrapper dispatch and a portable scalar oracle. SIMD reads must stay inside the selected32/36-character payload; malformed short inputs cannot authorize an overread. Full-bit comparison can use two unsigned big-endian machine words; benchmarking must decide whether that representation or fixed bytes gives better public pipelines. A call into generic128-bit arithmetic is not automatically an optimization. Clock transitions, serialization and secure entropy acquisition have ordering/IO obligations that are not made parallel merely by adding vector instructions.

Future independent reference fixtures should cover every accepted wrapper/case form; each bad dash/hex/length and nested wrapper refusal; receiver preservation on every error; all-zero/all-one and unrecognized version values; all16 comparison positions including high bits; append prefixes and alias ownership; and V4/V7 version/variant masks. V7 requires supplied-clock state cases for repeated fractional ticks, carry across milliseconds/seconds, subsecond rollback, whole-second rollback, range exhaustion and serialized shared use. Preserve independently supplied entropy bits outside the reserved masks. Test pure seams deterministically first, then actual IO providers and normal/poisoned owner checks. Benchmark complete parse/format/append/compare pipelines against scalar/reference variants with exact output fingerprints, not a vector kernel alone. No new reference generator build, Cinch source implementation or benchmark runs are part of this static review.
