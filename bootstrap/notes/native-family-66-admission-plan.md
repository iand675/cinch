## Required Native parity before a complete 66 claim

Native currently lacks the checked MVarCell carrier, kernel MVar effect,
14 intrinsic contracts and class/ownership lowering. The Rust resolved-scheme
exporter currently omits the MVar row, leaving those exports unresolved. A
separate proposal below covers this missing capability. This source curation
does not change the Rust metadata allowlist or claim that an unresolved export
is callable from Native. Completing a source51 fixed point on an unused subset
would not establish public MVar admission.

Explicit nominal Region must retain all source/public-header/private-resolved
and reexport identities. Defining unannotated legacy data remains accepted in
its existing source context; an exported Type parameter remains authoritative.
Native must not infer a replacement Region kind from a consumer's Mut row.
Open-row transport remains separate and unresolved where it was unresolved.

The new Rust Slots/Array work does not implement Native wide generic arrays.
Native's existing wide restrictions must remain named refusals until genuine
i128/boxed-word bridges and matching provider variants are qualified.

## Opaque callbacks and memory attributes

Current Native RuntimeIr emits no norecurse assertion. Preserve that
conservative property. Current Rust `recursive_units` seeds indirect applications
and opaque extern calls as callback-capable, follows their transitive closure
and direct cycles, and adds norecurse only outside that set. Native scalar and
foreign alias fusion proves a checked call target; it does not prove absence
of callbacks in arbitrary foreign bodies. Do not copy attributes from imported
metadata or serialized LLVM.

Future gates must retain the independent C callback-reentry trace (direct,
indirect, imported and transitive wrappers), count each callback exactly once
and inspect actual emitted attributes. The heap-callback consuming-apply repair
must remain in the selected seed. Boxed Nat comparison must be exercised
inside the newly compiled provider object, not merely a consumer-local wrapper:
large fresh operands in either position, retained aliases, O0/O2, checked RC,
normal/poison, and no reorder of drop before a payload read. Other boxed-reader
attributes also need a read-only audit; a repaired comparison does not prove
all runtime declarations safe.

## Staged qualification and resource plan

1. Freeze the published producer/runtime/source envelope after parent gates.
   Run strict snapshot claim verification, including every Rust/library claim,
   compiler/runtime binary hashes, target/word/endian/reclaim and all66 bytes.
2. Check the full curated51 source set and focused existing scalar667,
   authority27, alias trace/19+private20, loader9 cases, mutable88, nominal Region
   source/header/reexport/source-absent controls. A source-only check is not an
   emitter validation.
3. Build one fresh current-source provider with the actual230 requested roots,
   complete source closure and actual units; reject every hash, ABI, host,
   descriptor, interface, runtime and requested-variant mismatch. Include
   provider-internal boxed Nat and unsigned Neg/cross-signed conversion33+6.
4. Build a **fresh current-source Stage1** with the qualified new seed; do not
   reuse f811/e494/2c6d Stage1 files. Stop at the Stage1-only budget boundary for
   review. Target transient450–550MiB was the earlier estimate; remeasure before
   authorizing it with the new runtime/provider, and preserve a positive reserve.
5. Only after separate resource allocation, build Stage2 and Stage3 against the
   same admitted new provider. Require exact executable/interfaces fixed point,
   entry and source-absent consumers, changed-source probe, strict artifact
   mismatches, and all changed base API clients without source shadows.
6. A complete66 Native distribution additionally needs every MVar source,
   interface and runtime gate in the separate plan, with exact matched runtime.
   Keep any still unsupported payload/boundary explicitly open. No performance,
   provider or adoption claim follows from the static patch or one fixed point.

Historical f811/V2, V3, V4, source2c6d/bfd, compiler2f/4a/7a and their receipts are
not altered by this preparation. The old65 V5 b924/c4 plan remains a separate
historical plan; the current66 family must receive a new output directory and
receipt rather than relabeling that plan or an existing artifact.
