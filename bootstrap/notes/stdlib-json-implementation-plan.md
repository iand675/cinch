# JSON package implementation plan

The pinned cumulative package audit contains 92 declaration records: 73 historical/shared records and 19 facade records selected by the default `jsonv2` experiment. The pinned SDK enables this experiment internally even when `GOEXPERIMENT` is empty; its seven selected `v2_*.go` files define the actual reference behavior. Each record is mapped in `../evidence/stdlib/stdlib-json-capability-plan.json`. Existing `Text.Json`, `Data.Json` and `Text.Codec` remain unchanged. Their canonical-number/unique-key/strict-surrogate behavior is useful for compiler metadata and will not silently become general decoding behavior.

## Representation and syntax

`Text.Json.Value` will own one input snapshot and a private contiguous tape of nonrecursive token nodes. Opening-container nodes retain matched closing positions and the next sibling index; scalar nodes retain exact original byte spans. A reverse pass pairs container boundaries before immutable array construction. Object/array navigation therefore jumps subtrees without recopying the whole input or repeatedly parsing it. Exported raw buffers are copies. Strings are decoded only at value boundaries; original number lexemes and raw messages remain exact.

The parser uses explicit grammar and container stacks, not host recursion proportional to nesting. Only ASCII space, tab, CR and LF count as JSON whitespace. General decoding replaces invalid UTF-8 and unmatched surrogate escapes with the replacement scalar; raw syntax formatting preserves original string bytes/escape spellings. Duplicate object members remain ordered and are available to typed decoding's later-member updates. Existing canonical parsing continues to reject duplicates independently.

The new error vocabulary records original syntax offsets: offending characters include their encoded byte width, while incomplete token diagnostics retain the checkpoint appropriate to the operation, byte spans, type/value labels, object/field paths and optional causes. Integer and float number conversions return explicit invalid/range errors. Nonfinite floating values, malformed raw marshal results and invalid typed descriptors receive named errors; no silent conversion to null. Reflection-only invalid pointer targets become compile-time typed refusal or explicit descriptor errors, rather than fabricated runtime pointer objects.

`Valid`, compact, indentation and HTML escaping operate on bytes. Compact/indent preserve numeric and string-escape spellings; indentation preserves trailing source whitespace and drops leading whitespace. HTML escaping does not impose syntax validity. Checked append forms preserve an existing prefix. Normal string encoding replaces invalid byte-string input and handles control characters, quote/backslash, HTML policy and the two line-separator scalars. Raw message assignment/getters snapshot mutable storage; null and non-null empty raw messages remain distinct.

## Typed application values

`Text.Json.Codec` provides an explicit `JsonType a` capability carrying encoding, default construction, decoding/updating, zero/empty classification and labels. Primitive, nullable, sequence/fixed-array, binary, map and record descriptors compose it. Application records use typed projection/update callbacks and field descriptors with names, omission, quoted-number and embedding/priority metadata. There is no runtime-reflection claim.

Decode/update results retain the partially updated value and structured errors. Syntactically invalid documents are rejected before updates. Recoverable type/range errors preserve the first error while later independent fields continue; custom callback failures stop according to their explicit error outcome. Record lookup prefers exact names, then Unicode simple-fold matches; underscores/dashes remain significant in the default policy. A single folding helper depends on the separately tested `Data.Unicode.Kernel` scalar fold API, rather than changing ASCII `Data.Char` behavior.

Custom JSON/text/key codec factories provide the marshal/unmarshal capabilities. Marshal callbacks return owned raw fragments whose syntax is checked before formatting or writing; failures retain their original cause and type/path context. Existing `Text.Codec.JsonCodec` and `Data.Json` receive explicit bridge adapters, preserving their existing APIs. Active facade policy constructors are represented as immutable typed configuration values. Their meaningful descriptor policies and language-specific exclusions are reviewed separately; the entire experimental v2/jsontext package is outside this package claim.

## Incremental effects

`Effect.Json` uses a reusable incremental lexical state machine over owned chunks, with reverse fragment accumulation for an unfinished token/value. It never rescans the entire unfinished prefix after each byte. A source request is bounded; lookahead snapshots protect against mutable source-buffer reuse. Token, More and Decode share one grammar state and original byte cursor. Decode can advance one complete value within token iteration; unknown-field and numeric policies apply at typed decoding boundaries. Buffered returns a snapshot reader of unread lookahead. Source/syntax failures and recoverable typed failures preserve the advanced continuation distinctly.

Encoders render one value, apply indentation/HTML policy, append the required newline, and synchronously drain through the borrowed byte writer. Sink failures are sticky and inspectable; marshal errors do not poison subsequent encodes. Valid short writes are retried and invalid/zero progress is named. No borrowed descriptor is implicitly flushed or closed.

## SIMD, tests and gates

Exact bounded inline LLVM byte classifiers accelerate ASCII whitespace, string ordinary runs, digits and escaping predicates. Private loops use machine counters without wrapping-arithmetic proof clauses; public positions remain mathematical naturals. Owners span each raw traversal. All stores and complete-span copies use checked byte primitives. UTF-8 scalar/surrogate handling and block fringes remain explicit.

The independent generator covers default syntax/formatting, exact numbers/ranges, duplicate members, malformed bytes and offsets, surrogate replacement, RawMessage, typed records/maps/arrays/binary/custom methods, every token/Decode/More transition, offsets/buffering and encoder options. It stores arbitrary input/output bytes as hex. Facade policy fixtures use the same active default SDK and are labeled by the explicit configuration they exercise. Cinch controls add all split positions, reused one-byte buffers, retained branches, source/sink failures, partial decode updates, short writes, deep/wide inputs and ordinary-memory bounds. Foreign SIMD kernels compile for wasm32, AArch64 and big-endian PowerPC without claiming foreign execution.

Local implementation proceeds syntax/tape and format first, then typed codecs, then shared-state stream adapters. The first published checkpoint is a clearly partial source-backed value/formatting core, followed by typed codecs and effects. The complete package targets all 92 cumulative declaration records with implemented capabilities, tests and precise reviews of language-specific adaptations. The package remains partial until every record is accounted for. No stub exports are introduced to inflate coverage. Rust and frozen Native validation uses ordinary 32 MiB heap/8 MiB stack plus separate poisoned-free 256 MiB runs with zero live bytes/leaks. The public benchmark includes typed records, parse/format, exact numbers, raw messages, token/decode streaming and unchanged copy/runtime-hash controls, with independent checksums and retained assembly/allocation evidence. Heavy compilation, target builds and timings require the parent's CPU coordination.


## Core checkpoint boundaries

The core admits grammar-validated number spellings plus an explicit empty-spelling default. Its checked finite-float and signed-integer conversions cover that domain. Arbitrary numeric string casts, saturated/overflow result values, general typed conversion, custom callbacks, record/map descriptors and shared-state streams are not marked complete by the core checkpoint. The typed descriptor source is developed separately until its consumer fixtures pass. The Unicode dependency is published independently at `fee3e98e` (lane cherry-pick `ba68b029`); only JSON-specific commits are intended for integration from this lane.

The compiler host uses an explicitly recorded 64 MiB main stack. Compiled consumers keep their ordinary 8 MiB stack and 32 MiB heap, with separate 256 MiB poisoned-free runs. A retained first-generation fixture compilation overflowed the original 8 MiB compiler-host stack; it did not execute a consumer. Compact supported string literal emission reduces fixture syntax size. The original failing source is preserved, and a same-source 64 MiB host comparison remains a separate diagnostic until run.
