# Exact binary32 JSON conversion

This increment adds `json-number-float32` to the exact-number home and `json-float32-type` to typed JSON conversion. The independent binary32 algorithms live in `Text.Json.Binary32`. Checked conversions reject absent spellings and finite-range overflow. Typed failures preserve the previous representation, including negative zero. Existing binary64 conversion and formatting implementations are unchanged.

Parsing uses the binary64 decimal parser as an approximation and compares the original decimal spelling against exact adjacent binary32 midpoint rationals. A midpoint is `(2 × significand + 1) × 2^exponent`; its decimal coefficient uses bounded powers of two or five. Input coefficients retain every significant digit, including arbitrarily long suffixes. Normalization removes leading zeros and compares adjusted decimal exponents before lexicographically comparing zero-padded digit strings. Exponent parsing saturates at input length plus 1,000, which exceeds all relevant binary32 thresholds even after the source's fractional-digit adjustment. Midpoint ties select the even binary32 payload. The overflow midpoint uses the hypothetical next finite binary magnitude, 2^128. Applying the original sign after correction preserves signed underflow zero.

Formatting constructs the exact binary32 decimal coefficient, then tries one through nine significant digits. At each precision it first tests the closest ties-even coefficient, then the adjacent coefficient. The second candidate matters at asymmetric power-of-two rounding intervals: exact rational review identified three normal powers of two where the closest eight-digit coefficient fails to round back while its neighbor succeeds. Every candidate is checked with exact binary32 parsing. The first accepted precision is rendered using JSON fixed/scientific thresholds and explicit exponent signs. Nonfinite values retain structured value refusals.
