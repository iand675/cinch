# Linear shared write-all draining

`Effect.Stream.stream-write-all` previously copied the complete remaining suffix after every short write. A one-byte sink therefore requested a quadratic series of copies. The public signature and advanced-sink/error contract are unchanged.

The helper offers the original input once. A positive short result causes one private snapshot of the remaining suffix before another callback can mutate a retained earlier offer. Later offers are independently allocated windows: start at the observed progress, shrink after a short result, and double after a complete window up to 4,096 bytes. No previously offered buffer is mutated or offered again by the helper. Empty writes still invoke no callback; zero progress reports `StreamShortWrite(original total, confirmed sent)`, callback errors remain verbatim, and every error returns its advanced sink.

If the first accepted count is `p`, the first fresh window is at most `p`. Each later window is at most twice the immediately preceding accepted count. Total fresh offers are therefore at most `2N`; the private suffix snapshot adds at most `N` copied bytes. The helper's total copying and aggregate offered bytes are each bounded by `3N`, without assuming a particular short-write schedule. The original first offer is borrowed: the helper does not mutate caller input, while a custom sink can retain that original reference.

The independent fixture covers 64 KiB one-byte and variable schedules, original-buffer first offers, retained-buffer mutation, full acceptance, failures after an accepted prefix, zero progress, invalid callback counts and a nonempty continuation-epoch probe after each failure. It observes the complete accepted output separately from returned results. The one-byte case offered 163,838 bytes and the variable case 174,250, each below 196,608 (`3*65,536`). Every later offer is at most4,096 bytes, and the variable case grows to 512 bytes after complete windows.

A small linker wrapper counts real calls to the unchanged `cinch_bytes_copy` ABI, including fixture setup/output copies and trace rendering. All four explicit frontend/optimization combinations copy exactly 602,032 bytes, below the fixture-wide 673,024-byte bound. Rust uses compiler `cad70e533fcab8305fe6e79ae95f135f61252338c6a5fd5e5358e8f27563e3f4` and runtime `c4b1097b4b8e26541400228bdbbdcba1376101014823aeb2f5af619fbede57ac`. Native uses compiler `9e2a64e0e519fc908f17cd7329b72be90f1161513084bfe2e5e3ebbd4a846f90` with its exact copied provider/runtime snapshot. Both frontends are explicitly relinked at O0 and O2 with the counter object, separately from the Native wrapper's default link.

All eight same-source memory runs pass with zero live/leaked objects: ordinary 32 MiB heap/8 MiB stack and separate poisoned-free 256 MiB heap/8 MiB stack. The large controls peak at about 265 KiB during normal reclamation. The poisoned fixture peaks at about 13 MiB for Rust and 186 MiB for Native; this includes callback/telemetry allocation, and both remain below the specified 256 MiB gate. No consumer limit was raised. There is no timing/speedup claim in this checkpoint.

The preserved original source from `4c46a7a2` fails the identical functional and actual-copy gates with zero leaks. An independent offer-budget guard stops it after five calls, instead of allocating the entire quadratic series. It copies 787,651 bytes before stopping, versus the 673,024-byte fixture bound, and does not complete the two large writes. Its separate receipt preserves that failed baseline epoch honestly.

All 67 Stream declarations retain canonical documentation, with no diagnostics/orphans. The existing `lib_stream` Rust target adds the bounded regression; its coordinated Cargo gate remains parent-owned. Quoted-printable continues delegating to the shared helper, and JSON will consume this implementation rather than maintaining a second draining loop. JSON Codec drafts are excluded from this focused commit.
