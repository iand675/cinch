# Raw Number values and exact numeric error inputs

This increment completes arbitrary numeric string casts alongside the existing checked JSON-number factory. `json-number-from-text` preserves an unchecked scalar spelling; `json-number-from-bytes` snapshots arbitrary original bytes. `json-number-bytes` exports an independent exact copy, including malformed UTF-8. `json-number-text` provides the scalar-text projection and replaces each malformed byte explicitly. Checked numbers, raw scalar numbers and raw byte numbers have separate private constructors, preserving the existing checked-number fast path.

`json-number-int64-result` and `json-number-float64-result` return a `JsonNumericResult` containing both the numeric value and optional `JsonNumericError`. Syntax failures preserve zero. Signed integer range failures preserve the signed endpoint; floating overflow preserves signed infinity. Successful floating underflow preserves signed zero. Numeric errors retain the original function label, exact input bytes and explicit syntax/range reason. Scalar error-input views are projections; byte getters retain exact identity. Ordinary Result adapters are available when partial values are unnecessary. `JsonNumberError` and `json-error-numeric` preserve this metadata through custom, typed-cause and field-path wrappers. These are typed native adapters rather than claims of arbitrary runtime-error object identity.

Signed decimal parsing first accumulates an unsigned64 prefix, then checks the signed range after a complete unsigned parse. That order matters: `9223372036854775808x` returns syntax and zero, while `18446744073709551616x` returns range and the signed maximum because unsigned prefix overflow precedes the later invalid character. Signs and leading zeros are permitted; decimal integer separators remain invalid. No magnitude bignum grows beyond a machine word.

Floating casts accept validated decimal punctuation/separators, hexadecimal mantissas with required binary exponents, ASCII case-insensitive unsigned NaN, and signed infinity spellings. Decimal normalization validates every byte before calling the existing correctly rounded binary64 parser. Hexadecimal conversion retains sixteen significant nibbles, a sticky nonzero suffix, exact significant/fractional digit counts and a signed exponent bounded by four times input length plus 2,048. The bound remains safe after arbitrarily long significand cancellation. Quantization directly constructs IEEE64 normal, subnormal, zero and overflow representations with ties to even. The actual inline LLVM helper uses one block of selects and clamps every evaluated shift to 1..63, then selects defined zero-, 64- and wider-shift results. It contains no jumps, loads, stores or new runtime intrinsics. IEEE NaN classification is tested; unspecified NaN payload identity is not claimed.

The checked I64/F64/F32 helpers reject unchecked non-JSON spellings before runtime decimal parsing. Finite typed descriptors retain their previous policies. `json-number-type` validates raw spellings during marshaling; an absent spelling still emits zero, and invalid spellings produce an input-bearing custom syntax cause. Quoted numeric updates remain strict. Number's provided incremental encoder/decoder method adapters remain explicitly pending with Effect.Json.
