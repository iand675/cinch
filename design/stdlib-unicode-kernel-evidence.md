# Unicode kernel foundation

`Data.Unicode.Kernel` preserves the existing ASCII-only `Data.Char` contract and adds complete Unicode 17.0.0 scalar classification, simple upper/lower/title mappings, simple-fold successor/equivalence, Turkish/Azeri presets, and validated custom case ranges. Numeric `-code` methods retain invalid input observability: classification outside the code-point domain is false; named case/fold transformations preserve invalid codes; invalid general case selectors return U+FFFD. `Char` remains scalar-only. Generic range membership will separately permit the surrogate category through numeric input.

Custom case rules are sorted, disjoint scalar intervals with validated scalar-preserving mappings. Zero deltas deliberately override default mappings. Alternating mappings require the sentinel in all three case positions. Construction checks every rule before creating private owned bytes. Indexed observations preserve all 336 standard case ranges and all locale rules; frequently used mappings binary-search read-only packed data without copying entire tables.

The generated source holds 259 distinct named range tables, 7,235 original stride records, 4,352 class-page descriptors, 183 deduplicated pages, 4,758 runs and 1,021 metadata words. Classification preserves all categories, scripts, properties and fold memberships. Import/generation provenance is in `tooling/data/unicode17-tables.json`, with the original BSD license beside it. `import_unicode_tables.py --check` verifies the pinned SDK and `generate_unicode_tables.py --check` verifies reproducible source/layout output.

A dynamic LLVM extraction from a 256-lane constant vector passed both compilers but copied 2 KiB to the stack per call in optimized assembly. This representation was rejected. Bounded ordinary scalar case pages permit LLVM to emit direct private read-only table loads; pages have at most 64 alternatives and balanced routing. An optimized Native 64-word accessor has seven real instructions including bounds checking and the final return. Native's validation executable uses its default O0 link; optimized assembly inspection is distinct from runtime timing. No benchmark claim is made in this checkpoint.

The independent pinned SDK fixture covers all 1,114,112 numeric code points, valid scalar `Char` inputs, complete category/script/property/fold metadata, and reconstruction of every standard case range into the checked opaque custom-rule representation. Four modes each cover 544 chunks. Each compiler passes one complete normal run (32 MiB heap,8 MiB stack) plus 2,176 bounded poisoned runs (256 MiB heap,8 MiB stack), all with zero leaks: 4,354 processes total. Separate boundary/selector/locale/custom-refusal consumers pass normal and poisoned runs with both compilers, adding four processes. Six generator unit tests pass. Canonical documentation extraction covers 440 declarations with zero diagnostics or orphans.

The older 04be Native epoch rejects an otherwise valid generic `char-to-u32` wrapper while checking its scalar refinement. A Nat bridge adds allocations and was rejected; no contract was weakened. The 9e snapshot supplies the independently gated fix. Tooling selects that exact snapshot explicitly and never falls back.

`compiler/tests/lib_unicode_kernel.rs` adds a standalone Rust integration target with real Unicode 17 supplementary characters, fold cycles, custom override/fallback rules, checked refusals, wrong numeric inputs and canonical documentation. The exact runtime source passes the frozen compiler under both memory configurations. Cargo compilation is reserved for the parent integration lane and has not been run locally.
