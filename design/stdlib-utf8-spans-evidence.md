# Bounded UTF-8 byte spans

`Data.Bytes.Utf8` now provides two checked queries over an existing byte owner:

- `utf8-count-between :: Bytes -> Nat -> Nat -> Option Nat` counts the half-open span `[start,end)`. Invalid metadata (`start > end` or `end > bytes-len owner`) returns `None`; a valid empty span returns `Some 0`.
- `utf8-decode-between :: Bytes -> Nat -> Nat -> Nat -> Utf8Step` decodes at an absolute owner offset `at` within that span. Invalid metadata, `at < start`, or `at > end` returns `Utf8OutOfBounds`, U+FFFD, width zero. A valid `at == end` returns `Utf8End`, U+FFFD, width zero.

Each span is an independent arbitrary UTF-8 byte input. A continuation at its start and a scalar truncated by its end are malformed, even when surrounding owner bytes would complete an encoding. Every malformed nonempty step consumes exactly one byte as U+FFFD. All offsets remain ordinary mathematical `Nat` values until bounds have been checked; oversized values are refused before narrowing to machine offsets.

The queries retain the owner while reusing the existing exact decoder and count kernels. Count uses the existing sixteen-byte LLVM SIMD ASCII mask, eight-byte SWAR test, and scalar fringes bounded by `end`. Decode never inspects preceding owner bytes, and its remaining-byte bound is `end`. Neither API snapshots or mutates owner bytes or exposes a pointer. Query results still allocate ordinary scalar-count, optional and step values; avoiding a byte copy does not imply zero allocations.

The pinned SDK reference generator (`tooling/go_utf8_span_vectors.go`, version `go1.27.4`) calls the actual rune-count and decoding operations on bounded slices. Its fixture contains 1,505 arbitrary owner buffers, including all 256 single-byte values, deterministic malformed/Unicode corpus selections, and sixteen scalar/malformed patterns at all 32 source alignments. Every legal subspan is observed: 147,105 counts and 1,028,230 absolute-position decode observations, including positions before the span, at both boundaries and beyond the owner. Fingerprints include bounds, scalar, width and distinct status, in explicit little-endian wire order.

Both frozen frontends pass the complete corpus under a 32 MiB heap and 8 MiB stack, plus 189 independent poisoned-free groups under a 256 MiB heap and 8 MiB stack. Separate controls pass both memory modes on both frontends: reversed bounds, mathematical offsets beyond 64 bits, empty spans, interior continuation bytes, truncated endpoints, source aliases, mutation inside a span, and mutation outside a span that would otherwise complete a scalar. All 384 processes report zero live allocations and zero leaks. The supplied Rust consumer test exercises the same final controls; Cargo integration remains the parent's serial gate.

Rust uses compiler `f2d5ae4c…` with runtime `c4b1097b…`. Native uses the fully gated Char-contract compiler `9e2a64e0…`, source `0b11df4d…`, runtime `12945b71…`, and its matched provider/interfaces. The Native functional executable retains the wrapper's default O0 link. These are source-distributed byte-module tests; they require no new embedded registration or String helper epoch.

All 65 existing documented value/primitive bodies are byte-identical to the preceding checkpoint; the only declarations added are these two wrappers. The existing 22 read-only primitive bodies are unchanged. Their prior target/object and public scan benchmark evidence applies to the same implementations. Both current emitted call graphs were reviewed: the bounded count and decode pipelines reach no byte-buffer allocation, copy or mutation routine. Rust inlines the decode wrapper into the fixture's `Main.decode`; the count wrapper remains explicit. No new timing comparison or throughput claim is made for the wrappers.

The module now has 74 canonical documented declarations, with zero diagnostics or orphan comments. Exact source, fixture, compiler, provider, runtime, executable, codegen and memory receipts are retained in `benchmarks/stdlib/utf8-spans-evidence.json`. Reproduce the public controls with `tooling/validate_unicode_probe.py --kind utf8-spans`; reproduce the complete selected frontend corpus with `tooling/validate_utf8_spans.py`.

The five String-facing adapters remain a separate increment. Their source integration still waits for the fresh combined String/compiler/provider gate; these byte-span APIs add no dependency on `Data.String`.
