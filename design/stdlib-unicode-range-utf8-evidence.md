# Unicode range tables and raw UTF-8

This checkpoint adds `Data.Unicode`, `Data.Unicode.Range`, `Data.Unicode.Names` and `Data.Bytes.Utf8` to the previously tested Unicode 17.0.0 kernel. Existing `Data.Char` ASCII behavior and `Data.String` valid-UTF8/wrap-copy contracts remain intact. The numeric table APIs include legitimate surrogate membership such as category `Cs`; `Char` construction and UTF-8 scalar encoding reject that numeric class.

The Unicode facade preserves every built-in named category/script/property/fold table, all 262 exported table aliases, sorted catalog names/counts/lists, all 42 category aliases, exact 16/32-bit range fields, original strides and Latin offsets. Built-in queries read the compact immutable class database directly. Indexed/list observations construct only the requested safe values. Custom tables validate sorted disjoint bounds, nonzero full-width strides, Unicode limits and exact supplied Latin metadata before allocating private owned records. Malformed metadata has explicit named errors. Case-list and locale-list observations retain their exact original order and signed deltas.

`Data.Bytes.Utf8` supplies explicit forward/backward decoding steps, first/last/offset queries, scalar count/validity/first-invalid/full-prefix queries, numeric rune validity/length, encoding/checked encode-into/append, grouped and per-byte repair. Malformed input consumes exactly one byte as U+FFFD, including truncations. End and beyond-end offsets consume zero bytes with separate statuses. Invalid numeric encodings emit U+FFFD while rune-length returns `None`. Encode-into returns written width and writes nothing on insufficient capacity or an invalid offset.

All repair/append/encode byte results are fresh, including valid and empty inputs. Replacements can be arbitrary non-UTF8 bytes; the raw repair APIs never silently coerce them into `String`. Separate mutation tests prove that source/replacement aliases do not alter already returned results. Complete ASCII blocks use read-only eight-byte SWAR high-bit scans; non-ASCII decoding uses exact four-byte or short-tail loads, shortest-form checks, surrogate exclusion and U+10FFFF limits. All mutations use checked language writes or bulk range copies; source owners remain live across raw loads.

Independent public SDK observations cover all 1,114,112 numeric code points, every 65,536 byte pair and 12,773 malformed/Unicode/alignment rows. The UTF8 consumer hashes complete forward/backward position/width/status results, valid/full-prefix/count/first-invalid observations and every encoded byte, then checks exact grouped/per-byte repair outputs. Each frontend passes one complete normal 32 MiB/8 MiB run and 1,000 bounded poisoned 256 MiB/8 MiB runs: 2,002 processes, all zero leaks. Separate atomic-capacity/invalid-number/alias/freshness tests and full named-table observations pass normal and poisoned runs on both frontends, adding eight processes. The catalog consumer covers all 260 map entries, all 262 exported table aliases, exact original records, owned reconstructions, endpoints/stride holes, surrogate/raw-invalid policy, all list/index adapters and checked metadata refusals.

Actual retained UTF8 primitives compile to wasm32 and AArch64 objects without foreign execution. `lib_utf8` supplies the additional powerpc64 big-endian Rust-emitter object gate; that Cargo target is reserved for parent integration and has not been run locally. Canonical extraction covers 182 new declarations with zero diagnostics/orphans, in addition to the foundation's 440 declarations. Ten generator/corpus unit tests pass. Reproducible generators and original source/license provenance remain in `tooling/data`; exported alias observations are produced by a separate SDK consumer rather than reading the packed implementation.

Rust remains frozen compiler `f2d5ae4c…` with runtime `c4b1097b…`. Native remains fully gated Char-contract compiler `9e2a64e0…`, compiler-source `0b11df4d…`, matched runtime `12945b71…`. Exact seed/provider/runtime/source/fixture/executable/report identities are in `benchmarks/stdlib/unicode-range-utf8-evidence.json`. Native's default validation link is O0. Its large single-literal UTF8 test consumer compiled in 143 seconds, while Rust O2 compiled it in 5.5 seconds; these are fixture compilation observations, not library runtime benchmarks. The complete normal consumers then took 11.7 seconds and 1.0 second respectively. Public pipeline timing and generated hot-loop inspection continue separately.

`tooling/data/unicode-capabilities.json` maps all 344 cumulative Unicode and 23 UTF8 declarations from the actual pinned SDK. Historical Version records map to the current 17.0.0 edition only. The current raw byte APIs implement all 18 non-String UTF8 declarations. Five valid-String facade adapters await the separately registered `Data.String` provider epoch and the strings lane's private-backing helpers; the count/validity contracts already follow from `string-length` and valid `String` construction. Arbitrary invalid SDK string data is represented by the byte APIs. No normalization, expansion or full case-folding capability is claimed.

Run `validate_unicode_probe.py --kind catalog --frontend rust|native` for exact named-table observations, `--kind utf8-ownership` for independent ownership/refusal checks, and `validate_utf8.py --frontend rust|native` for full domain/byte coverage. The full runners freeze source identities and reject reuse after source/compiler/provider/runtime/fixture/executable changes.
