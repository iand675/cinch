# Fixed color palettes

The pinned `image/color/palette` surface has two records. The actual installed tables contain256 Plan9 entries and216 WebSafe entries,472 total. The exact order, RGBA8 representation and opaque alpha are preserved. `sdk-surface.json` and `operation-map.json` record the actual declarations, source/executable hashes and capability mapping.

The isolated `Image.Color.Palette` module exports `color-palette-plan9 :: Unit -> ColorPalette` and `color-palette-web-safe :: Unit -> ColorPalette`. Each call constructs an immutable value through the public `Image.Color` constructors. A caller can retain several palettes and build modified sequences explicitly. There is no mutable process-wide table in the API. The existing Color151b source is an unchanged dependency.

Source generation extracts exact packed RGB values from the pinned table source. Groups of eight color/list constructors keep the source bounded and avoid an intermediate packed-word list. Channel extraction is constant scalar work; public nearest-color use reaches the already qualified four-channel distance SIMD path through `Image.Color`. The factory itself has no artificial SIMD claim or external runtime dependency.

The actual SDK oracle captures all472 ordered raw/canonical entries, each exact entry's Index/Convert/Model result, and512 adversarial query colors through both tables. Queries include every gray byte and deterministic full-width RGBA16 values with zero, near-zero, partial and opaque alpha, including representable channels above alpha. A separate scalar validator derives the entire Plan9 cube and WebSafe grid independently, then recomputes first-nearest selection with per-channel truncation. No expected value comes from the Cinch source.

`prepare_color_palette_source.py`, `capture_color_palette_reference.py`, `validate_color_palette_reference.py` and `check_color_palette_source.py` maintain the corresponding stages. Source checks use a fresh project, exact frozen compiler/runtime identities,64MiB compiler-host stack and350/250MiB storage guards. All first failures remain plain in their original projects. Runtime O0/O2, normal/poison ownership, actual public SIMD reachability/portable objects, SDK-free CI and public performance are separate pending gates until their receipts exist.
