# Random-library source qualification

This experiment follows the immutable static proposal at `6fea5bb3`. Only source checks and actual canonical-documentation extraction are authorized here. No IR, SDK build/generator, linked consumer, target runtime or timing has been executed. The complete prime-generation dependency gap remains unchanged.

Each unit uses the exact frozen compiler `ffb5d39c42d0446a912b6027ebbe88bd825f5c6d91065aeb8a2048526c4999b9`, CPU4, a private store/scratch directory, a 320 MiB starting guard, 250 MiB reserve, 5 MiB fresh-payload cap and fifteen-second wall cap. `inputs.json` enumerates the exact candidate and recursively copied nonembedded dependency closure. Embedded modules, including `Data.Bytes` and `Data.Core`, remain authoritative in the compiler. No Core/Bytes source override is copied. Dependencies are committed Root sources at `f30db145`.

Original `6fea5bb3` modules and static manifests are unchanged. Every first compiler diagnostic remains plain. The first `Text.Token` proposal fails the effect-containment rule because its declared pure LLVM primitives contain stores. The corrected `candidates-v2/Text.Token.cinch` returns values from pure eight-byte vector arithmetic, uses SWAR for the eight-byte fringe and performs bounded stores through the existing `Data.Bytes.Word` surface. This avoids a containment bypass or an invented mutation capability. The sixteen-byte loop applies two vector transforms. The existing word writer currently performs individual byte stores; this is a known implementation cost, not a claim of vectorized memory stores or benchmark speed.

Seven components now pass source and canonical-documentation gates across nine units. The other first failure is `Data.Prime.Candidate`: an unannotated local numeric branch selected `Int` where `Nat` was required. Its separate correction adds two explicit Nat literal annotations without changing the algorithm. This candidate-shaping acceptance does not close the full prime-generation gap. `manifest-partial-v1.json` preserves the earlier five-unit headroom-hold checkpoint; `manifest-source-v2.json` records the completed source/doc checkpoint. The compiler launch transport failure is preserved separately in `launch-failures.json` and created no process or source unit.

Source acceptance does not establish correctness of output, probability properties, ownership under generated code, LLVM validity or performance. Actual SDK fixtures, public consumers, poison/leak tests, LLVM/assembly inspection and portable targets remain separate future gates. In particular, source checks do not prove that a compiler keeps an otherwise unused strict mutation result alive or retains its owner correctly.

Each unit contains exact copied sources, canonical documentation JSON, complete stdout/stderr and an execution receipt. Store/build payloads remain plain locally and are listed with hashes in the evidence manifest; they are not duplicated into the published lane. The initial launcher is preserved under `launchers/`; later units carry their own exact launcher snapshot.
