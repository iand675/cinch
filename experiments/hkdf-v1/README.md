# HKDF capability candidate

This is an isolated source-qualified experiment. The pinned cumulative `crypto/hkdf` surface contains exactly three records: generic Extract, Expand and Key. `sdk-surface.json` records the real declarations and exact SDK/library/runtime source hashes. The exact ffb5 compiler has accepted the candidate, actual IO/Mut callback composition and its canonical documentation, and refused pure effect erasure/private constructor access. `source-gates.json` retains all commands and defining artifacts. No SDK build, candidate runtime or timing program has run yet.

`Crypto.Hkdf` maps those operations to explicit one-shot digest and direct-HMAC capabilities. An opaque `HkdfHash` stores only checked block/output widths; the real callback is passed separately under `forall (fx :: Row)`. Every callback effect remains in the operation result row. Prepared private pads are scoped through a continuation instead of an unproved row-indexed nominal carrier. Direct HMAC providers take the separate checked output-width capability, without a fake block-size argument. Pure Digest conveniences adapt all four existing SHA256/SHA512/SHA1/MD5 selectors; SHA256 uses the existing dedicated HMAC primitive. Root's `Text.Digest` source, exports and runtime are untouched.

The capability contract is the hash of complete byte messages, with exact advertised widths and explicit Result errors. It does not copy a mutable hash-object model, constructor identity, Reset/Write counts or ambient service-indicator state. Zero block/output widths and digests larger than their block widths are supported. Descriptor errors concern only the byte-buffer representability domain; there is no algorithm-name blacklist. The generator includes noncryptographic test-only hash shapes to demonstrate those structural properties, rather than presenting a short selector list as generic parity.

Salt is `Option Bytes`. None means the required output-width zero salt; Some empty means an explicitly supplied empty HMAC key. These agree for conventional hashes but can differ when output width exceeds block width, because HMAC first hashes an oversized key and truncates it to the block. Primary context is Bytes, preserving every string octet, including malformed UTF8 and embedded zeros. Text conveniences explicitly encode UTF8. Primary requested length is Nat, so negative lengths are unrepresentable. The oracle retains the actual SDK negative-length panic separately instead of pretending it is a typed length error.

The255-times-width calculation uses exact natural arithmetic. Native signed-integer overflow for pathological, physically unmaterializable reference hash metadata is not copied as HKDF semantics or advertised as generic byte-for-byte parity.

Output length is checked against the precise255-block bound. Exact255-block requests succeed; the next byte is a typed error before MAC work. Zero output is a successful empty result. Combined Key validates original IKM once and performs extraction even for zero requested output. Expand validates its original PRK. Optional caller policy runs before protocol length errors and has no implicit access to process-global policy. Explicit FIPS-only reference runs and matching caller policy can therefore preserve original-key/error precedence without banning other algorithms in the general primitive.

Original secret, salt and context are snapshotted before caller callbacks. Policy receives another private copy. Digest messages contain copies of private pads; direct HMAC calls receive isolated key/message copies. Provider output width is checked and its bytes are copied before they become the next block or final output. Retained/reused/aliased callback buffers cannot change earlier copied blocks through later serial mutation. One owned final output buffer is filled through checked bulk copies; no partial key escapes on error. Generic pads are prepared once per key with checked eight-byte word reads/writes and scalar fringes. Pure LLVM kernels XOR packed values only; they perform no pointer accesses or stores. Existing checked word operations retain backing owners and normalize wire order. The earlier uncompiled pointer-store draft is preserved separately and is not selected for source qualification.

`rfc5869-vectors.json` retains the seven AppendixA cases plus the pinned SDK's extra explicit nil/empty case3 variant. `reference.go` calls the actual installed SDK operations, captures whole outputs/errors/panics and observes original input aliases. It provides RFC, standard-width/length, custom-shape, salt and explicit policy process families. It does not replace HKDF or HMAC in the reference. `validate_hkdf_reference.py` independently constructs HMAC pads and the HKDF counter chain using independent digest implementations and a scalar specification for the custom fixture hash; it validates complete bytes, fixed RFC outputs and exact policy/length error precedence.

The first source epoch is candidate401c / compilerffb5; BDF is recorded only as the exact future link archive. All source/CIF/diagnostic files remain plain. The preceding0ded draft never reached a compiler and is not a passing source epoch. Preserve the first failed project and diagnostic in every later gate; do not narrow callback effects or rewrite metadata. SDK execution, independent validation, IO/Mut callbacks, retained-buffer/error/width controls, actual kernel canaries/portable objects, both optimized runtime profiles, source-absent metadata and SDK-free maintained CI remain pending. The detailed plans are `qualification-plan.json` and `performance-plan.json`. The static set must remain below5MiB. All Color/Palette/Multipart/QP inputs and Root/inventory/pins remain unchanged.
