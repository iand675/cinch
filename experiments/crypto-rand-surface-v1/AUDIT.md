# Cryptographic random surface audit

Status: read-only reference audit and uncompiled static proposals. No SDK build, compiler, proposed runtime, fixture generator or benchmark was executed. Root/prelude/inventory and every sealed provider input remain untouched. The existing lane is reused; no checkout or agent was created.

The pinned reference is SDK 1.27.4, whose non-test `crypto/rand` source declares exactly five public objects. Reference names appear here and in the independent fixture generator; proposed public Cinch comments describe their own contracts without cross-language comparisons.

| Reference surface | Current Cinch coverage | Isolated proposal / remaining limit |
| --- | --- | --- |
| `Reader io.Reader` | System source is implicit behind an explicit `Io r` capability; no mutable global reader | Explicit `ByteReader r` and raw `BufferSource r` continuations; actual system reader convenience. No global source replacement. |
| `Read([]byte) (int,error)` | `random-bytes` returns a fresh owned buffer; no public in-place fill | `Effect.Random.Buffer` fills a caller buffer using a temporary owned draw. The extra allocation/copy is explicit. Provider failures remain the runtime boundary; callback errors are typed results. |
| `Int(io.Reader,*big.Int)` | `random-nat-below` already handles arbitrary-precision `Nat` bounds, unbiased by rejection of a whole multiple before remainder | Add reader-aware natural/signed adapters and an alternate masked comparison algorithm. Current large-bound semantics exist but have not been independently qualified across this new fixture matrix. |
| `Prime(io.Reader,int)` | No maintained public probable-prime generator found | Concrete candidate shaping only. Full generation remains blocked on maintained primality/policy foundations; see `PRIME_API.md`. |
| `Text() string` | Hex tokens and UUIDs exist; no corresponding uniform-alphabet secret-token convenience | `Effect.Random.Text`, with pure `Text.Token` SIMD/SWAR mapping and explicit-source variant. |

## Exact reference contracts

`Read` fills the entire destination and returns its length with nil error on success. A reader failure leads to an irrecoverable runtime failure, rather than a normally returned non-nil error. It uses the public global Reader; an application override can therefore alter its source. An empty request does not call a custom reader. Cinch's existing empty system draw intentionally retains its device-open check; this proposal does not rewrite that integrated contract.

`Int` always uses its supplied reader in this SDK version. Its bound is a mathematical signed big integer, must be positive and otherwise causes a panic. Bound one returns zero without invoking the reader. It sizes the candidate from `BitLen(max-1)`, masks excess high bits, decodes big-endian bytes and retries candidates at least the bound. Reader errors, EOF/partial EOF and callback progress are observable. The existing Cinch `Nat` operation is already arbitrary precision; `random-nat` alone is the separate fixed 64-bit convenience. The proposed signed adapter returns a named invalid-bound result instead of a panic and never narrows through I64.

The existing whole-multiple/remainder algorithm and the alternate masked algorithm are both unbiased with uniform independent input. They do not have identical byte consumption or performance: a bound just above a power of two can cause about half of masked candidates to be rejected while the existing whole-multiple algorithm accepts nearly all full-byte candidates. Do not describe the alternate as universally faster. Its reader behavior matches the independent reference algorithm and removes large-number remainder work; benchmarking must include those tradeoffs.

The requested `Text.UUID` label is not an actual module in the audited Root source. The existing candidate modules are `Data.Uuid` and `Effect.Uuid` under `experiments/uuid-candidate-v1/sources/`; the packed parsing follow-up is separate. Their formatting/parsing, version 4 generation and explicit version 7 state remain identifier APIs. This audit records both candidate source identities and does not infer that a missing `Text.UUID` module means UUID functionality is absent.

`Prime` rejects FIPS-only policy before it checks `bits < 2`. For permitted policy and size, it masks the high byte, forces the highest two bits and odd parity, then accepts a candidate only after `math/big.ProbablyPrime(20)`. That routine combines small-prime screening, Miller–Rabin rounds and an extra-strong Lucas/Baillie–PSW component; a handwritten twenty-round test is not an exact replacement. Since SDK 1.26 the supplied reader is ignored by default. Only the deprecated `GODEBUG=cryptocustomrand=1` branch selects it, with an optional nondeterministic one-byte probe. The default uses the internal secure reader, even if the public global Reader changes. Compatibility fixtures must record the selected mode and must not assume an exact optional-probe count.

`Text` currently draws 26 independent bytes and maps each low five bits to `ABCDEFGHIJKLMNOPQRSTUVWXYZ234567`, yielding 26 independent symbols and 130 bits. Its public contract is at least 128 bits and permits future output growth. It is not ordinary Base32 serialization of 16 bytes: that also gives 26 characters but constrains the last symbol and carries only 128 input bits. UUIDv4 has fixed RFC fields and 122 random bits, so UUID formatting is not the missing secret-token operation. UUIDv7 carries time/state fields and is likewise a different API.

## Reader and capability adaptations

`ByteReader r` already returns an explicitly advanced handle on success or failure. Its positive empty chunk means EOF; it cannot directly encode a zero-byte nonterminal read or simultaneous bytes plus failure. The `Effect.Random.Uniform` simple-reader overload is documented within that contract. It preserves each existing `StreamError` as a structured value.

The raw `BufferSource r` contract already preserves signed count, bytes, optional status and the advanced continuation. `Effect.Random.Read` supplies the concrete exact-read adapter: zero invokes no callback; invalid counts are rejected before copying; positive prefixes are copied into private storage; full final data succeeds even with a simultaneous error; partial EOF is distinguished from initial EOF; zero/no-status retries the advanced source. It does not introduce an arbitrary retry budget or a sticky error that the source did not retain. Raw-source uniform adapters use that operation and return the advanced capability on every path. Existing direct-transfer/proxy capabilities are retained by returning the actual advanced source rather than reconstructing a stale wrapper.

The source error vocabularies are Cinch's structured StreamError/BufferError, not arbitrary foreign error-object identity. An application diagnostic can be retained as a BufferCustomError value. This is an explicit type adaptation, not a claim to preserve cross-language pointer identity. Default secure operations always use system entropy; explicit-source operations have only the statistical/security quality their source supplies. Deterministic reader fixtures are models, never substitutes for actual-provider qualification or timing.

## Concrete files and dependency limits

Seven proposed modules are isolated under `proposed/`. `Data.Nat.Bytes` supplies read-only big-endian import, including bit 63 and arbitrarily many 64-bit chunks. It deliberately does not use the unrelated private byte-hash conversion that clears the high bit. Word reversal/masking uses inline LLVM and bounded `Data.Bytes.Word` loads. `Text.Token` uses a sixteen-byte LLVM vector block, an eight-byte SWAR block and exact scalar fringes. Private pointer operations retain both owners and never load/store beyond tested range guards. Source-first checks, LLVM/assembly retention and portable object gates remain future work, not completed qualifications.

All proposals use existing public arithmetic, bytes, string and stream/buffer capabilities. Full prime generation is intentionally not supplied. Modular exponentiation can be constructed from existing multiplication/remainder, but there is no maintained public primality/modular-exponentiation foundation to substantiate the required probability/edge-case behavior, and no equivalent enforced-policy capability was found. Those are maintained-verification dependencies, not a claim that arithmetic makes the algorithms impossible. No new runtime foreign ABI or fake primality primitive is invented.
