# Future actual-provider benchmark plan

No new timing or build is authorized by this plan. Preflight source, SDK fixtures, public behavior, owner boundaries and leak checks first. Use fixed compiler/runtime/source/common objects with explicit identities, and obtain a separate exclusive CPU lease before collecting performance samples.

Compare complete token pipelines: system entropy to `random-text` (currently26 independent symbols), reader-based tokens with an actual secure source, and pure SIMD/SWAR symbol mapping as a separate kernel/control. Do not compare token formats by character count alone or treat UUID text as a 128-bit secret. Pin the actual SDK Text source/version; its length may grow in future versions. Model Reader substitution is not allowed in actual-provider timing.

For uniform arbitrary bounds, include 1, 2, 3, 127/128/129, 255/256/257, 2^64−1/2^64/2^64+1, 2^128−159, 2^256+1 and 2^521−1. Separate the existing whole-multiple/remainder API from the proposed masked/default and callback paths. Include actual entropy bytes consumed and rejection-count diagnostics outside timing. A power-of-two-adjacent bound can favor one rejection scheme and penalize the other; retain that outcome rather than assuming the alternate is faster. Pure candidate decode and source/copy/continuation allocation controls explain costs without replacing real entropy in end-to-end measurements.

For filling, compare fresh byte allocation, proposed in-place filling and callback filling with explicit destination ownership. The current proposal uses a temporary owned draw/copy; do not present it as a zero-copy runtime intrinsic. Keep zero-length provider/callback semantics distinct. Use complete output observations and retained owners after the closing clock; report GC/RC and temporary-buffer differences honestly.

Prime performance remains blocked until maintained generation exists. Once available, qualify exact sizes and probability/policy/error behavior before time comparisons, with small/medium/large bit widths as separately bounded units. Actual default generation uses actual system entropy. Deprecated custom-reader or deterministic candidate fixtures are functional models, not performance substitutes.

Every future timing unit must preserve all controls, failures, regressions, raw varied checksums and complete sample ranges. Rotate variant order per condition, record warmups separately, pin CPU/runtime settings, and capture actual quota/load/throttling before and after. Source/compiler/runtime/SDK changes create new epochs. The prior provider window is independent evidence; it does not establish speed or qualification for this new surface.
