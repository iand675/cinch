# Entropy helper qualification

The isolated proposal now passes six deterministic loop tests and actual x86_64 Linux backend/helper execution. These qualify the copied sources only. No candidate runtime archive, Cargo build, public `cinch_random_bytes` ABI/ownership gate, cross-target execution, or benchmark has run. The production runtime source and frozen D91 archive remain unchanged.

`REVIEW.md`, `manifest.json`, and `static-review-receipt.json` are retained as the original static stage. Their statements that code had not run describe that earlier stage. The copied Linux backend's header also contains a historical statement that no Linux column had run; it remains plain and unmodified as baseline provenance. The new evidence executes only this proposed x86_64 backend/helper path, with no new aarch64/x86 execution claim.

The exact proposed entropy module SHA256 is `a9a70f3b731a01bf59f54115572214638d918789566655ed34f005e5cafbf893`; the copied proposed Linux backend is `70c40717c5a56feb5cdbbef0f966c081014e9c48e98b5c5a4aff33c1699f0f92`. Both gates used rustc 1.100.0, commit `0ef1bc386059596dada8fb65b50425aab2ea637a`, LLVM 23.1.5, executable SHA256 `5073422953727c9427a76b7fce03aa9404da46315e5a1e4965389512a41e8db0`. Each receipt records full paths, source hashes, exact CPU-4 commands, statuses, stdout/stderr, output sizes, and disk guards.

All six deterministic tests passed against the exact source through a panic-only syscall stub: empty loop; fallback failure; invalid count rejection; ordinary errors without fallback; partial reads interleaved with interruption; and ENOSYS suffix fallback. The test binary was 889 KiB including nearby logs/receipt, and this gate made no real entropy calls. The compiler's three dead-code warnings are retained; they arise because provider functions are deliberately unused by this loop-only wrapper.

The actual-provider wrapper includes the exact copied Linux module and supplies only its unchanged parent constant `EINVAL: i64 = 22`. The forwarding seam calls the actual inline assembly backend; there is no replacement entropy source. The backend's assembly retains normal compiler memory effects because it declares neither `nomem` nor `readonly`, and its existing architecture register/clobber declarations are unchanged. A direct 16-byte draw returned `(16, 0)`. Exact fills succeeded twice each at 0, 1, 16, 255, 256, 257, 4096, and 1,048,576 bytes. Seventeen length-prefixed records retain every byte drawn by that capture unit. Their format, lengths, complete-file check, and SHA256 are recorded in `actual-syscall-v1/run-1/capture-and-trace-review.json`. Freshness assertions at lengths at least 16 are smoke checks, not statistical certification.

Both untimed syscall traces succeeded. Between explicit BEGIN/END writes, the 16-byte helper performs exactly `getrandom(..., 16, 0) = 16`, with no entropy-device open/read/close. The empty helper performs only `/dev/urandom` open/close, preserving the existing empty-request provider check. The raw traces also retain an unrelated startup `getrandom(..., 8, GRND_NONBLOCK)` call before the markers; it is not counted as the helper draw. This evidence establishes the intended syscall shape on this host, not a measured public-pipeline speedup.

The deterministic gate produced about 0.85 MiB; the actual-provider gate produced about 2.38 MiB including its approximately 2 MiB raw entropy capture. Both started above 350 MiB free and remained above the 250 MiB reserve with no 30 MiB output-limit breach. Wall times in the receipts are process bookkeeping only, not benchmark observations. CPU 4 was explicitly returned after each unit.

Next useful bounded branch checks would inject ENOSYS or EPERM into only the helper's `getrandom` call using a supported syscall tracer, preserving all traces and expected-error exits as injected evidence. ENOSYS should open/read/close the real device and complete; EPERM should fail without device fallback. Such injection would test actual error plumbing but would not establish an old kernel or sandbox's natural behavior. The public Bytes/ownership, actual consumer, symbol, portability, and matched timing gates remain outstanding and separately scheduled.
