# Matched actual-entropy public pipeline benchmark

Prepared only. No benchmark compile, preflight, SDK probe or timing has started. The previous fresh pair and 28 linked functional processes are published in `39cf0ceb`. This plan uses those exact plain archives and frozen C2, with one fixed source/LLVM/common object linked separately to baseline and candidate. The original D91 and earlier SDK measurements remain historical controls under their original identities.

`protocol.json` defines 13 conditions: real `random-bytes` at 0, 1, 16, 32, 256 and 4096 bytes; version4 generation; version7 actual clock/state/entropy generation; fresh allocation controls at 0, 16 and 4096 bytes; a machine counter/observation control; and a real wall-clock control. Dispatch, argument parsing, empty initial owner and version7 generator construction occur before the start clock. U32/U64 inline LLVM counters, wrapping checksums and packed UUID field observations avoid natural loop metadata allocation. Random bytes come only from the actual public capability, with no injected or seeded source.

The source carries the newest owned byte result through the loop, returns it with invariant/observation counts, and reads it after the closing clock. Each new value replaces the previous owner; the last owner is released after its post-clock observation. This includes allocations and preceding-result releases in the loop, while the final result release and report formatting occur after the end clock. UUID conditions include the public mutable byte snapshot on every iteration. The allocation control makes a changing byte write observable so that a pure zeroed buffer cannot silently become one prepared constant. The counter and clock controls retain only their initial empty owner.
