# Complete matched entropy window

The candidate reduced the median time of the 1-, 16- and 32-byte public entropy pipelines by about 73%, and secure UUID generation improved 3.06× for version4 and 2.64× for version7. This is one complete host window with the fixed compiler/source/common object and freshly matched runtime pair. It establishes a provider improvement for this configuration, not SDK or platform parity.

The lease completed in 11.269 seconds, below its 45-second cap. All 1365 raw observations are retained: 195 warmups and 1170 timed samples, 30 timed samples per condition/variant. Every condition used all six variant orders exactly five times, with each variant at every position ten times. The raw sequence exactly matches the sealed plan. All 33 before/after input hashes match; the actual cgroup added zero throttled periods and zero throttled microseconds. Affinity, quota, load and runnable-process boundary snapshots are retained. Every process passed structural validation.

`all-conditions-table.md` reports every condition's median ns/op, including all controls and the SDK reference. `sample-ranges.md` reports complete minima/maxima and paired candidate/baseline ratio ranges. `analysis.json` retains all 30 values for each variant, median/mean, interpolated p10/p25/p75/p90, standard deviation and all paired ratios. No sample, warmup, control, regression or outlier was removed or normalized away.

For actual nonempty draws, the baseline/candidate median speedups are 3.797× at 1 byte, 3.734× at 16, 3.766× at 32, 1.892× at 256 and 1.081× at 4096. The 4096-byte distributions overlap and some individual pairs regress; the result is a median improvement, not an assertion that every call is faster. UUIDv4 changes from 1185.22 to 386.98 ns/op, and UUIDv7 changes from 1384.76 to 524.62 ns/op.

Controls remain explicit. Allocation at 4096 bytes regresses by 1.79% in the ratio of medians; counter by 0.32%; clock by 0.10%; empty allocation by 0.03%. Allocation at 16 bytes improves 0.58%. The unchanged empty-device entropy path has a ratio-of-medians value of 0.955 but a paired-ratio median of 1.0146 with broad overlapping ranges, so no arithmetic/provider-optimization cause is claimed for that movement. Several counter/clock observations have large relative outliers despite quiet quota counters; those remain visible. Stable control medians do not mean every control observation was stable.

The candidate remains slower than this SDK reference: 2.65× at 16-byte entropy, 1.90× at 32 bytes, 1.14× at 256, 1.34× at 4096, 3.54× for UUIDv4 and 3.23× for UUIDv7. At one byte the gap is 5.35×. The SDK's secure kernel vDSO path is proven by a syscall stack and a separate 17-draw trace. The candidate intentionally uses one raw syscall per nonempty draw. The allocation controls also expose different RC/GC release behavior; their SDK comparison is not used to adjust the entropy results. Zero-byte SDK reads omit the legacy device-open check preserved by Cinch, so their large difference has a distinct API/provider boundary.

All numbers refer only to the current sealed reference source and executable. Earlier D91/SDK generation observations had their own harness/compiler/source identities and uncertainty; they are not relabeled as this result. This measurement followed 325 structural benchmark preflights plus the separately recorded runtime and actual public-consumer gates. There was no subsequent timing window or retry.
