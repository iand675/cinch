# Constant-time operation qualification

`Crypto.ConstantTime` implements seven scalar and buffer operations. The nested
data-independent timing scope remains open because it also needs runtime task
inheritance and foreign-call state restoration. Branch-free code and timing
measurements do not establish hardware instruction timing guarantees.

The selected source is identified in
[`stdlib-constant-time-results.json`](../../bootstrap/stdlib-constant-time-results.json).
It records both frontend epochs, bounded ownership observations, exact outputs,
actual guarded loads, scalar/traversal SSA audits and foreign object emission.
The maintained compiler target is `lib_constant_time`.

The equality baseline is the preserved initial implementation with mathematical
loop indices and a SIMD block worker. The selected implementation keeps the
same complete traversal but uses private machine offsets. The buffer benchmark
instead compares the selected packed implementation with a benchmark-only
byte-at-a-time implementation generated by removing the packed fast paths.
Neither comparison measures against an external library implementation.

Both drivers prepare buffers before the clock, use an opaque iteration token,
consume complete outcomes, validate aliases and run normal/poison preflights.
Timings use ordinary generated reference counting with allocation counters
disabled. Raw samples, controls, source/artifact hashes and quota statistics are
preserved in the two result JSON files beside this page. Constant-time behavior
is reviewed separately from benchmark throughput.

To reproduce equality from a clean checkout, select a compiler and its matching
runtime archive explicitly and use a fresh output directory:

```sh
python3 tooling/bench_constant_time.py \
  --compiler /path/to/cinch --runtime /path/to/libcinchruntime.a \
  --clang /path/to/clang --artifact-root build/equality-new-epoch \
  --output build/equality-new-epoch-results.json --samples 7
```

The runner emits both source closures before linking. It refuses a nonempty
artifact directory so a new compiler does not replace earlier measurements.
An existing preflight can be reused only when compiler, observer, sources,
support code, runtime, LLVM and executable identities all match.

To reproduce conditional-copy and XOR pipelines:

```sh
python3 tooling/bench_constant_time_buffers.py \
  --compiler /path/to/cinch --runtime /path/to/libcinchruntime.a \
  --clang /path/to/clang --artifact-root build/buffers-new-epoch \
  --output build/buffers-new-epoch-results.json --samples 7
```

Packed writes currently use the existing checked byte stores. Direct stores in
pure inline LLVM are excluded by the primitive containment policy. Improving
that path requires a sound compiler operation with complete bounds, ownership
and backend support; bypassing the policy is not an optimization.
